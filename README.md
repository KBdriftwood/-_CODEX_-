# LP VISION — 設備配置シミュレーター

現場写真にLPガス設備の簡易3Dモデルを重ね、提案用の完成イメージをPNGで保存するWebアプリです。写真は固定し、設備だけの位置・回転・表示サイズ・見え方を調整します。写真の外部送信、ログイン、クラウド保存はありません。

## Windowsで確認用ファイルを開く

**まずは [確認用ZIP](preview/LP-VISION-check.zip) を保存して展開し、中の `LP-VISION.html` をEdgeまたはChromeで開いてください。** GitHubのファイル画面では、ダウンロード（下向き矢印）または「View raw」からZIPを保存できます。詳しくは [確認版の開き方](preview/README.md) を参照してください。

`dist-standalone/LP-VISION.html` は、3D表示・操作画面・サンプル背景を1つにまとめた確認版です。このファイルをパソコンに保存し、右クリックの「プログラムから開く」でEdgeまたはChromeを選びます。ZIPで受け取った場合は先に展開してください。Node.jsやアプリのインストール、Webサーバー、インターネット接続は不要です。

チャット内の画像リンクはアプリを操作する画面ではありません。確認用HTMLはブラウザで開いて操作します。ページの終了や再読み込みで編集状態は初期化されます。

開発者は次のコマンドで、現在のソースから確認用HTMLを再作成できます。

```sh
npm run build:standalone
```

この確認版も仮モデルを使用します。Windows実機の動作確認は別途必要です。将来GLBモデルに交換して単一HTMLとして配布する場合は、そのモデルデータもHTMLへ埋め込む対応が必要です。

## 開発時の起動

Node.js 22.12以降（この環境では24.19）とnpmを使用します。

```sh
npm ci
npm run dev
```

起動時にターミナルに表示されるアドレスをブラウザで開いてください。Windowsの現行Edge・Chromeを主な利用対象とします。3D表示にはWebGL 2が必要です。開発サーバーの公開や本番デプロイは行っていません。

このクラウド環境でnpmの標準キャッシュに書き込めない場合は、次のようにします。

```sh
npm ci --cache /tmp/lp-vision-npm-cache
```

## 操作

1. 初回は同梱の「サンプル背景（イラスト）」と仮バルクが表示されます。
2. 「写真を読み込む」で現場写真を選びます。JPEG・PNG・WebP、30MB以下、4,000万画素以下に対応します。JPEGの向き情報も反映します。HEICは事前にJPEGなどへ変換してください。
3. 「移動」を選び、写真上をドラッグします。数値入力とスライダーでも横位置・縦位置を指定できます。位置は設備の足元を基準に、写真の左上からの割合で管理します。
4. 「設備の回転」で左右の回転・前後の傾き・左右の傾きを調整します。ドラッグでは左右の回転と前後の傾きを変更します。
5. 「カメラ」で設備を見る方向・見下ろし角度・遠近感（画角）を調整します。ドラッグでは見る方向と見下ろし角度を変更します。背景写真は動きません。
6. 「写真上の表示サイズ」で表示倍率を調整します。モデルの実寸情報は変わりません。
7. 「PNG保存」で写真と設備を合成した画像をダウンロードします。

作業領域にフォーカスがある場合は矢印キーでも操作できます。Shiftを押しながらのドラッグ・矢印キー操作は微調整になります。

「初期状態に戻す」は写真を残して、設備の位置・回転・表示倍率・カメラ・操作モードを初期化します。写真の差し替えでは配置情報を維持します。ページの再読み込みや終了時には編集状態は保存されません。

## 仮モデルについて

横置きの円筒、丸い端部、支持脚、簡易バルブをプログラムで組み立てています。全長4.0m、タンク直径1.4m、高さ約2.2mは操作確認用の仮寸法で、色・マークも架空です。メーカーの正確な製品モデルではありません。

画面と保存PNGの両方に仮モデルであることを明記します。実際の寸法や安全距離を写真から計測する機能、写真の前景による設備の自動遮蔽、写真に合わせた照明の自動推定はありません。影も簡易表現です。

## PNGの配置・画質

写真の縦横比を保持し、画面と保存時に同じ配置状態とカメラ計算を使います。保存時は元写真の画素サイズを基準に、長辺最大4,096px（端末の描画上限が低い場合はその上限）まで出力します。小さな画像は拡大しません。保存PNGには仮モデルの表示が入り、操作用のUIは含めません。

## 構成とモデル交換

React・TypeScript・Three.js・Viteを使用しています。

| 場所                          | 役割                                         |
| ----------------------------- | -------------------------------------------- |
| `src/App.tsx`                 | 写真の切り替え、編集状態、リセット、保存操作 |
| `src/components/`             | 作業領域と日本語の操作パネル                 |
| `src/state/editor.ts`         | 位置・回転・表示倍率・カメラの状態と範囲     |
| `src/models/catalog.ts`       | 設備情報、仮寸法、モデルの読み込み方式       |
| `src/models/equipment.ts`     | 仮モデルの生成とGLBの読み込み                |
| `src/scene/EquipmentScene.ts` | 3D描画、写真に対する位置、カメラ             |
| `src/export/exportPng.ts`     | 写真と3Dの合成、PNGの保存                    |
| `src/assets/sample-site.svg`  | 自作の操作確認用背景イラスト                 |
| `tests/editor.spec.ts`        | ブラウザによる操作・画像出力の検証           |

モデル交換時は設備定義の `asset` を `{ type: 'glb', url: '/models/bulk.glb', scaleToMeters: 1 }` にし、対応するファイルを配置します。GLBは外部ファイルを参照しない自己完結した形式を推奨します。`scaleToMeters` は元データをメートル単位へ変換する倍率です。読み込み時に足元中央を配置基準に揃えます。標準方向は長手方向がX軸、上がY軸、正面が+Zです。

正式モデルへ交換する際は実際の寸法・表示名・仮モデル表記・サムネイルも確認してください。現在の仮モデル表記は正式モデルへの誤認防止のため固定です。実製品データでの読み込み確認はまだ行っていません。GLBがなくても、写真や寸法図から簡易モデルを改良できます。

## ビルドと検証

```sh
npm run build
npx playwright install chromium
npm test
```

システムにChromiumがあるLinux環境では、ブラウザの追加ダウンロードをせずに次のように検証できます。

```sh
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm test
```

自動テストでは3Dの実描画、マウス・数値・スライダー・キーボード操作、リセット、写真の差し替え、不正ファイル、縦長・横長PNGの画素比較、画面サイズ変更、JPEGの向き、大画像の縮小、狭い画面を確認します。テスト用の画像はその場で生成し、実際の現場写真は使いません。

単一HTML版のテストでは、HTML本体だけをブラウザへ渡し、ネット接続と追加ファイルの読み込みを禁止した状態で、写真・3D操作・PNG保存を確認します。この環境のChromiumは管理ポリシーで `file:` を禁止しているため、ファイルを直接ダブルクリックする動作はこの環境では検証できません。

Windows上のEdge・Chromeで、利用予定の現場写真を使った表示・操作・ダウンロードの確認は別途必要です。
